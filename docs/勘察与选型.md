# 勘察与选型

这份文档记录项目开始前的三个前置判断，以及它们如何决定了技术路线。
所有数值都来自测试机实测。

> 测试环境：HarmonyOS 4.3.0（Android 12 / API 31），屏幕 1316 × 2832，
> 无 root。项目与任何厂商无关，此处仅作环境说明。

---

## 1. 系统世代：能不能用 ADB

第一件事是确认设备是否兼容 ADB。判据很简单：

```bash
adb devices -l
```

| 结果 | 含义 |
|---|---|
| 能看到 `<serial>  device` | 系统提供 ADB 兼容层 → ADB 方案可用 |
| 始终为空，但已开调试 | 可能是纯血鸿蒙等不提供 ADB 的系统 → 需换方案 |

本项目的测试机属于前者，因此确定走 **ADB + 桌面脚本**的路线。

同时确认了基础参数：

```bash
adb shell getprop ro.build.version.release   # 12
adb shell getprop ro.build.version.sdk       # 31
adb shell getprop ro.product.cpu.abi         # arm64-v8a
```

---

## 2. 渲染方式：能不能用无障碍

第二步决定"用控件点击"还是"用图像匹配"。

```bash
adb shell uiautomator dump /sdcard/ui.xml
adb pull /sdcard/ui.xml
```

解析结果：

| 指标 | 实测 |
|---|---|
| 节点总数 | 9 |
| 带 `text` 的节点 | 0 |
| 带 `resource-id` 的节点 | 0 |
| `clickable=true` | 0 |
| 最大层级深度 | 6 |

同时 `dumpsys SurfaceFlinger --list` 里能看到该应用的
`SurfaceView[...]` 层。

**结论**：画面由单一 Surface 渲染（Canvas 系引擎），
无障碍树里没有任何可交互控件 → **图像匹配是唯一可行路线**。

幸运的是窗口没有 `FLAG_SECURE` 标志，`screencap` 能拿到真实画面。

---

## 3. 导出产物：到底能拿到什么

第三步要确认"保存到相册"产出的文件长什么样。做法是：手动保存一张，
然后对比保存前后的目录差异。

实测结果：

| 问题 | 结论 |
|---|---|
| 分辨率 | 500 × 350 PNG（无损），是资源原始尺寸，不是截图缩放 |
| 边框 / 水印 | 无。纯插画，不需要裁剪 |
| 文件名 | `<毫秒时间戳>.png`，含精确时间，不含其他语义 |
| 存放位置 | 相册根目录，与相机照片混放 |

这带来两个直接影响：

1. **不需要做图像处理**：拿到即是成品，无需裁剪、去水印
2. **不能靠"整个目录打包"归档**：目录里混有用户的私人照片，
   只能按"保存动作前后新增的文件"精确抓取

同时确认了：该应用没有批量保存功能，一次只能保存一张。

---

## 4. 由此确定的方案

| 层 | 选择 | 理由 |
|---|---|---|
| 采集 | 桌面脚本 + ADB | 调试快、日志完整、不需要打包安装 |
| 定位 | 模板匹配 | 无控件可点 |
| 点击 | `input swipe`（长按） | `input tap` 会被引擎吞掉 |
| 成功判据 | 目录出现新文件 | 唯一可信的信号 |
| 归档 | 明文目录 + JSON 清单 | 脱离程序也能读懂 |
| 浏览 | 本地网页 | 零安装、零联网 |

### 为什么不做"纯手机 App"

技术上可行（MediaProjection + 无障碍手势），但：

- 需要用户授予屏幕录制与无障碍权限，**商店审核对无障碍极不友好**
- 调试成本高，且无法在没有设备的情况下迭代
- 桌面脚本可以在 30 分钟内验证一个假设，App 要 30 分钟打包安装

因此把脚本作为第一阶段，App 作为后续可选项。

## 5. 路线演化：从网格到滑扫

第一版按"6 个格子逐页点选"实现，遇到三类问题：

1. 页码推算与真实页码不一致（应用重启后相册回到第 1 页）
2. 卡片是"先选中、再点一次打开"，点击被吞时会打开上一张
3. 排序方式会改变内容顺序

第二版改为**滑扫**：详情页支持左右滑动，于是采集变成
「保存 → 左滑」的循环，不再依赖网格坐标、页码与排序。

这次转向把状态机的复杂度降了一个数量级，详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

---

## 6. 一个反直觉的细节：导出比截图更清晰

直觉上"截图"应该和"保存"差不多，实测不是：

| 指标 | 数值 |
|---|---|
| 屏幕显示尺寸 | 1024 × 717（原图的 2.05 倍） |
| 原图锐度（高频能量） | 5.064 |
| 截图锐度 | 2.469 |
| 原图放大到同尺寸后锐度 | 2.672 |

截图只是把 500×350 的图放大后重新采样，**细节更少**。
所以采集必须走应用自身的导出，截图只用于定位按钮。

---

## 7. 遗留问题

- 地点、日期等语义元数据应用未提供，只能靠时间戳推断顺序
- 非明信片类内容（手工制品、摆件）没有导出入口，不在本工具范围内
- 坐标与分辨率绑定，换机型需要标定
